# 手机本地工作空间

侧栏的“日常”沿用已有 API 聊天；“本机 Codeb”使用手机 Termux 中的官方 Codex；“远程 Codex”保留 SSH 服务器连接。
聊天、供应商和 SSH 配置没有迁移或清空。升级请覆盖安装，保留原包名及签名。

## 准备 Termux

需要 ARM64 Android。进入“本机 Codeb 设置”，按安装 Termux、准备运行环境、授权并检查三个步骤操作。已有 Termux 无需重装；下载按钮使用 Codeb 自有域名的官方原版安装包，对应源码与许可证同目录提供。不同来源签名不同时不能覆盖安装，请保留原 Termux 和数据。

设置中的“复制命令并打开 Termux”提供以下准备命令：

```sh
curl -fL --retry 2 https://codeb.baiyun.si/tools/codeb-phone-setup.sh -o ~/codeb-setup.sh && bash ~/codeb-setup.sh
```

脚本备份并开启 `allow-external-apps=true`，仅补齐缺少的工具，通过 Codeb 域名的软件源入口验证 APT 签名，下载并校验固定版本的官方 Codex。返回 Codeb 后允许系统提示的 Termux 命令执行权限；设置页检查当前步骤，准备期间可自动刷新，也可手动点“检查环境”。准备失败会显示阶段，可修复后重新运行。
通过“Termux 后台运行设置”打开系统应用详情，在耗电管理中允许不受限制地后台运行。一加 Android 16 即使选择“完全允许后台行为”，仍可能冻结 Termux 的通信进程。Codeb 在本机连接期间绑定 Termux 原生命令服务，并每两秒通过 Binder 唤醒后台通信；断开连接或连接失败会取消唤醒并解除绑定。普通权限和 Root 都可使用，不需要修改系统冻结设置或安装额外服务。其他厂商系统尚未逐项验证。

本机 Codeb 的设置分别选择 **Responses** 供应商与模型；Root 开关保存普通/root 权限。后续进入沿用选择，通过顶部设置可修改。
先点“检查环境”，缺运行时可点“一键部署”。Termux 未开放外部命令时，可复制首次准备命令到 Termux 执行，再返回检查。Codex 原生需要 Responses 接口；仅支持 Chat Completions 的供应商仍可用于日常聊天。
首次连接下载固定的官方 Codex 0.162.0 ARM64 musl 运行时，并核对 SHA-512。Codeb 不修改全局 npm 安装、默认软件源或原来的 `~/.codex`；准备脚本使用独立的软件源清单。
它不在每次打开时自动追最新版；升级运行时须重新验证协议和设备能力。

## 权限及数据

- 普通：进程使用 Termux 的 Android UID，直接文件访问遵循 Android 权限。
- Root：需要 KernelSU、Magisk 或兼容的 su 授予 Termux root；连接时验证实际 UID 为 0。未授权时不会静默降级为普通权限。
- 普通模式不会主动提权，但如果 Termux 本身已被 KSU 授予 `su` 能力，它不是阻止恶意提权的独立安全沙箱。模型指令禁止调用 `su`/`sudo` 不能代替操作系统隔离。需要严格隔离时，应使用没有 root 授权的独立运行环境。
- 显示路径使用 `~/Codeb` 与 `~/Codeb-root`，提供指向旧工作目录的短链接，现有文件不搬迁；Codex 会话在对应的 `homes` 目录。项目选择只是工作目录，不是文件访问沙箱。清理 Codeb 聊天缓存不会删除这些 Termux 文件。
- 模型请求使用所选供应商，仍会产生其正常用量；本地 CLI 不是离线模型。
- 后台运行仍受 Android 和 Termux 的进程、电池管理约束。

## 文件、供应商与 Skill

设置中可启用或关闭供应商，关闭后不参与本机模型选择。先选择供应商，再选择其模型；本机模型设置不修改 SSH 服务器的模型默认值。

日常、本机及远程的顶部菜单均可打开文件管理弹窗；聊天中的实际文件链接可直接打开编辑器。日常管理当前对话文件，本机/远程浏览所连接环境，可浏览当前 Android 身份有权访问的目录。支持新建、导入导出、重命名、删除文件和空目录，以及 Markdown、文本、图片、PDF 预览。PHP 等源码按文本打开，不执行。ZIP/APK/JAR 仅预览目录，不解压。

文本编辑默认按屏幕宽度自动折行，可纵向滚动；显示折行不会向文件插入换行符。预览和导入上限 18 MiB，UTF-8 文本编辑上限 1 MiB，单目录最多 5,000 项，压缩包最多显示 2,000 项。保存前检查文件版本，其他程序已修改时拒绝覆盖，需重新打开。

工作模式使用 Codex 原生 Skill：在项目 `.agents/skills/名称/SKILL.md` 中编写说明，重新打开项目加载，再从输入框“+”选择。独立 Codex home 内附带 `codeb-phone` 操作说明，不改变原有全局 Skill。

## 手机操控

在工作设置中打开系统无障碍设置，为“白云Codeb”授权，再启用“手机操控”。需要 Android 11 及以上；不需要 root。首次启用当前供应商/模型时发送无隐私的随机数字测试图，确认模型确实读图后才放行。失败保持关闭，可以换模型或重试；通过结果在本机缓存，更换地址、密钥、接口或模型后重新测试。

开启后，模型可通过官方动态工具读取截图和界面文字，点击、滑动、输入、返回或回到桌面。截图发送到当前供应商，界面文字视为不可信数据。可拖动的悬浮球展开后可暂停/继续、阅读 AI 输出、回到当前对话或停止操控；任务结束显示完成标记。暂停会中断当前执行，继续会从当前状态重新观察并续做；离开工作模式、切换模型、断开连接也会撤销授权。锁屏、密码输入、受保护截图与系统权限授予不开放给工具。每次操作前必须先观察当前界面，坐标按真实截图尺寸换算。

## 本机连接

APP 通过 Termux 官方 RUN_COMMAND 启动随 APP 提供的小型本机适配程序，它把经过双向认证的回环连接转接到官方 `codex app-server --listen stdio://`。
随机会话凭据验证成功前不发送中转站密钥。密钥仅送入当前 Codex 进程环境，不放进启动 Intent、命令参数或生成的 TOML。
网络适配使用带随机认证的本机 CONNECT 代理，由 Node/Android 解析 DNS，TLS 保持端到端；普通模式不需要 root DNS 服务，也不改变系统 DNS。
连接结束时关闭官方进程与网络适配器。Root 进程被拒绝时，在所用 root 管理器检查 Termux 授权。

手机方案参考 [codex-termux](https://github.com/xkxxs/codex-termux) 对官方 musl 运行时的适配思路；Codex 二进制仍来自 OpenAI 官方 npm 发行。

## 检查

`node tools/check-local-runtime.cjs` 检查启动参数、分段握手和代理认证。JVM 的 `LocalRuntimeTest` 检查旧连接兼容性和本机 RPC 权限参数。
`PhoneToolRpcTest` 验证手机动态工具的数字及字符串请求 ID 原样返回，避免工具已完成而 Codex 一直等待。
`LocalRuntimeDeviceTest` 是显式硬件检查，要求已安装 Termux/Node、开启外部调用、授权 Codeb，并且 KSU 授权 Termux。
它使用临时假 API 密钥，不请求模型；实测普通/root 身份、文件编辑、命令、文件预览和普通 UID 不能直接读取 root 私有工作目录，结束恢复供应商列表。

## 远程同步与后续消息

日常聊天与本机 Codeb 都支持引导和排队：运行中输入文字或附件后显示两种发送方式，默认排队。日常 API 的引导会取消当前请求，保留已有回复，把新提示连同上下文重新请求；本机使用 Codex 原生引导。正常完成后自动执行队列，手动停止则保留并暂停待执行消息，可再点击卡片继续。

点击停止立即结束页面的运行状态，保留已有结果；有草稿时也保留独立停止按钮。本机同时撤销手机操控，后台异步寻找实际活动回合并中断。中断超过 8 秒或失败、或创建会话时还没有可中断的会话 ID，会关闭这次本机运行时，需要重新连接后继续。旧请求和旧回合的迟到消息不会重新激活任务；停止不能撤销已经完成的文件修改或点击操作。

支持原生共享服务的 Codex 使用官方 `app-server daemon` 和 `app-server proxy`，手机经 SSH 连接同一后台；无需额外服务器组件。任务运行时，输入内容后才显示“立即引导”和“排队发送”，默认排队。输入框上方的待执行卡片可删除或立即引导该条文本；引导在 Codex 下一个处理输入的时机生效，不会强行终止正在运行的命令。带附件的已排队消息暂时保留排队发送。服务器明确拒绝引导会恢复队列；网络结果不确定时保留可恢复文本，避免自动重发造成重复。

排队由官方 Codex 在当前轮结束后自动执行。独立旧 CLI 仍持有写入锁时自动同步和重试，释放后恢复可写；不会杀进程或删除锁。工具详情默认折叠，只有手动点击才展开；Markdown 宽表格可横向滑动。
